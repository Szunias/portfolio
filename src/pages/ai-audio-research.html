AI Audio Research

For my graduation thesis I built an Unreal Engine 5 client that asks for sounds during play and a Python server that generates them with AudioGen, MMAudio or the ElevenLabs API. I measured how long each sound takes to arrive after its gameplay event, then built the cache, pregeneration and procedural fallback that hide the wait from the player.

From event to sound

I compared a procedural DSP baseline with four AI setups, timing every request in Unreal from the gameplay event to audible playback, so the request, generation or transfer, decoding and playback all count. Only the procedural sound fits the 100 to 150 ms the thesis allows for footsteps, impacts and UI sounds. A repeated or predicted AudioGen footstep gets inside that budget through the cache and pregeneration.

From Unreal to the server and back

Each sound starts as a text prompt from a gameplay component in Unreal: an AnimNotify on the run animation for footsteps, physics events for landings, trigger volumes for ambience zones and the UI for clicks. A C++ WebSocket client sends the prompt to the Python server. The audio comes back as PCM on a network thread, and a task-graph dispatch builds the USoundWave on the game thread, where Unreal requires it.

The server runs AudioGen and both MMAudio models on the laptop’s 8 GB GPU and passes ElevenLabs requests to the cloud. Unreal already holds 4 to 5 GB of that memory, so the server tracks VRAM, unloads the least recently used model when another needs room and can keep a busy one pinned. Each result is trimmed, normalised and cached as PCM under a hash of prompt, engine, duration and sample rate, up to 500 MB in RAM with a copy on disk.

Because a first generation takes seconds, the server watches the game state and prepares what the player is likely to trigger: approaching a door prepares the door sounds, entering the forest prepares its ambience. A repeated request comes from the cache instead of the model, and while a model is still loading, requests fall back to cached or procedural sound.

A result counts as failed when it is silent, misses its length by more than 20%, takes over 10 seconds or crashes the decoder. The server then retries once with a new seed, tries another model and hands over to the procedural sound. In a stress test of 500 generations per method, between 24 (ElevenLabs) and 69 (MMAudio Large) failed; procedural DSP never did. Back in Unreal, each cached sample is varied with a pitch shift within 2 semitones, a volume change within 3 dB, a low-pass for occlusion and the reverb of its zone.

Same prompt, four methods

For the thesis I rated 60 anonymised samples, 12 per method and loudness-matched to −18 LUFS, on a scale from 1 to 5. ElevenLabs averaged 4.3, MMAudio Large 3.9, AudioGen 3.6, MMAudio Small 3.5 and procedural DSP 2.4. I was the only rater.
