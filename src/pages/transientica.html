Training and gameplay in Unity

Players record ten examples of each beatbox sound with their own microphone. The trained model then classifies live hits while the game judges their timing against a beatmapped song.

Audio path

Microphone input to timing judgement

The current build runs entirely inside Unity, without Python, OSC or an external machine-learning package.

The microphone writes into a pre-allocated ring buffer. An onset detector sends a 512-sample window through my FFT, then KNN compares spectral centroid, rolloff, flux, zero-crossing rate, RMS, attack time and flatness with the player’s training examples.

The game matches the classified hit to the nearest note on AudioSettings.dspTime. It compensates for the analysis window and stores the recurring microphone offset measured during a 100 BPM calibration pass; manual adjustment is available in 1 ms steps.

Signal path Microphone → onset → 512-sample FFT → seven features → KNN → nearest note → score.

Architecture

Python prototype and current C# build

The first prototype used an SVM in Python and sent classifications to Unity over OSC. I replaced that path with an in-game FFT, feature extractor and inverse-distance KNN classifier.

Training data now stays in readable JSON and can be updated between rounds. The rebuild also added song selection, beatmaps, scoring, combos, grades and saved results.

The published accuracy and latency figures apply only to the Python SVM prototype. The C# KNN build still needs the same held-out dataset and end-to-end timing protocol before the two versions can be compared directly.
