AudioQ

A sampler and effects chain built in C++ with JUCE 8.

AudioQ loads a sample, runs it through granular, filter, dynamics and glitch processing, and exposes 16 automatable parameters to the host.

Solo developer · C++17 · JUCE 8 · MIT

Signal path

From loaded file to output

Every processor has a fixed place in the chain, so saved state and host automation produce repeatable results.

Sample or loop region → granular playback → filters → compressor → tremolo → glitch effects → dry/wet blend.

WAV, AIFF and MP3 files load into a draggable waveform. The player can select a loop region, add an optional loop crossfade and use a manual 20–300 BPM resampling control.

The DSP uses JUCE StateVariableTPT low-pass and high-pass filters and a JUCE compressor. Custom processors provide tremolo, bitcrushing, stutter and chunk reverse.

04

Peak fail-safe

Playback stops when the internal monitor exceeds 4.0 linear gain, roughly +12 dB. This is an additional fail-safe, not hearing protection.

Engineering notes

Granular peaks and filter topology

Granular peaks. Overlapping grains can produce large level jumps. The compressor handles ordinary peaks and the separate monitor stops playback above the safety threshold.

Filters. The filters use JUCE’s StateVariableTPT implementation. The public source does not currently support a claim of explicit incoming-parameter smoothing.

Compatibility. AudioQ is documented as VST3 and standalone. A verified OS, DAW, sample-rate and channel-layout matrix is still pending, so this page does not claim universal DAW support or host-tempo sync.
