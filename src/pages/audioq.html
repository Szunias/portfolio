Overview

One sampler instead of three plugins

Every time I wanted to mangle one sample, I loaded a granular plugin, then a filter, then a tremolo, and routed audio between all three. AudioQ collapses that repeated chain into a single window: drop in a WAV, AIFF or MP3 and every tool is already connected.

The first version had granular, tremolo and filters. The rest arrived when real editing sessions exposed gaps: a compressor because granular playback spikes, bitcrushing and stutter for harder transitions, reverse for risers, dry/wet for parallel blends, and region looping so rhythmic material stays on the project tempo.

Everything is exposed to the host through APVTS, so all 16 parameters automate from the DAW timeline.

One editing pass

You drag a door slam onto the waveform, enable granular mode and shrink the grains until the slam becomes a metallic drone. A filter sweep and a touch of bitcrush later, you have a texture that started as a door, and you never left the window.

Signal path

What happens between the file and the output

Every block sits on one fixed signal path, so automation always hits the chain in the same order.

One fixed DSP order, from loaded file to output.

Playback starts from the loaded sample or a loop region you drag directly on the waveform. Granular mode chops it into grains of 0.05 to 0.5 seconds and randomizes playback; grain size and density decide whether the note becomes a shimmer or a drone.

From there the signal runs through the filters, the compressor, the tremolo and the glitch section. A dry/wet control blends the result against the original, and a live output display shows exactly what the chain is doing to the waveform in real time.

The chain Sample or loop region → granular engine → LPF / HPF → compressor → tremolo → bitcrusher, stutter, reverse → dry/wet → peak safety.

The interface

Ten blocks, one window

Source waveform on top, live output below it, and every processing block laid out in a row. Nothing hides in submenus.

AudioQ · standalone window 16 parameters
01

Granular synthesis

Grains of 0.05–0.5s with randomized playback, controlled by size and density. A piano note turns into a pad, a door slam into a metallic drone. This block is the reason the plugin exists.

02

Filters

Low-pass and high-pass across 20Hz–20kHz on JUCE's StateVariableTPT topology, with smoothed parameter changes so cutoff automation stays clean across the whole range.

03

Compressor

Threshold, ratio, attack, release and auto make-up gain. Added specifically because granular playback spikes; it tames peaks before they reach the output.

04

Tremolo

A hand-coded per-sample sine LFO, 0.1–10Hz with depth control. I squared the LFO shape because the raw sine felt flat; the squared curve moves more musically.

05

Bitcrusher

Bit depth from 16 down to 1 and downsampling up to 40x. Neutral at full quality, lo-fi crunch and aliasing as you push it, for making clean samples sound broken on purpose.

06

Stutter + reverse

Both pull from the same 1-second history buffer. Stutter repeats a captured chunk at 2–32Hz; reverse plays 180ms chunks backwards. Together they make glitchy, broken textures.

07

Tempo + looping

Playback resamples from 20 to 300 BPM, and loop regions are drawn by dragging on the waveform, so a 2-bar drum break stays locked to the project tempo. Optional crossfade on loop points.

08

Dry/wet + peak safety

Dry/wet blends the processed signal against the original for parallel textures. Peak safety watches the output and stops playback above +12dB. It is a fail-safe against runaway granular spikes, not a substitute for monitoring at a safe level.

Edge cases

Automation spikes, tempo loops and file loading

A plugin has to survive whatever a user automates at it. Most of the engineering went into the parts you only notice when they fail.

Granular peaks

Random grains kept stacking into painful volume spikes.

Granular playback overlaps randomized grains, and every so often several loud ones landed together. The output jumped far past the level of the source sample, which made aggressive settings genuinely unpleasant to explore.

I attacked it from two sides. The compressor with auto make-up gain tames the ordinary spikes, and a separate safety monitor stops playback outright above +12dB. Aggressive settings became far less risky to explore.

Automation

Sweeping the filter cutoff produced zipper noise.

A DAW sends parameter changes in steps, and applying them directly to the filter made every fast cutoff sweep crackle. The classic beginner filter topology also got unstable near the extremes of the range.

I moved to JUCE's StateVariableTPT topology and smoothed every incoming parameter change before it reaches the DSP. Cutoff automation now sweeps cleanly across the full 20Hz–20kHz range.

Loop timing

Looped breaks drifted against the project tempo.

Free playback is fine for drones, but a 2-bar drum break that ignores the session BPM is useless in a real arrangement. Cutting the region by hand and hoping it matched was exactly the workflow I built the plugin to avoid.

I added tempo-aware resampling from 20 to 300 BPM and draggable loop regions on the waveform itself, with an optional crossfade on the loop points. Rhythmic material now locks to the project and stays there.
