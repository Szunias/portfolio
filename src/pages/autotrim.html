AutoTrim Exporter version 3.4.4

I designed and built AutoTrim Exporter, a REAPER tool for delivering sound effects. It gathers a sound’s layers from several tracks, trims the silence around them without cutting the attack or the tail, and verifies every render before the named file reaches the delivery folder.

Designer and developer · Lua ReaScript · ReaImGui · REAPER 7.37+ · Windows, macOS and Linux

Export

Sound effects rarely sit on one track: an impact, its debris and a sub layer can be three items on three tracks, with a long ambience running underneath. I built Export around the item that anchors the sound. Select overlapping collects the items on other tracks that overlap it, leaves the long ambience out and frames the result in the arrange view without moving anything on the timeline.

Trim & fades

Adaptive silence finds where a sound starts and where its tail ends, each against its own threshold, and widens both by a pre-roll and a safety ending so the attack and the decay stay whole. Presets start from the kind of sound: one-shots, tails and impacts, or ambiences. For a long tail that is still ringing, a third pass may scan up to 30 seconds.

Loudness

A delivery keeps its original level or is levelled by one of LUFS‑I, RMS, Peak or True Peak under a true-peak ceiling. Quick targets cover a mobile game at −16 LUFS, streaming at −14 and EBU R128 at −23. Whichever mode is chosen, Peak and RMS are measured after export and stored with every verified delivery, and LUFS‑I is added when the optional SWS extension is installed.

Format & metadata

The Game / Wwise profile renders 48 kHz, 24‑bit WAV and leaves the level untouched, because game audio ships dry and the middleware owns the final level. Positional sounds usually go out mono, so the channel policy is set per batch. A saved profile keeps format, loudness, destination, naming and metadata together; names can follow UCS 8.2.1, and each batch can get a delivery report with a verdict for every file.

History

History lists every verified file with its path, length and Peak, RMS and LUFS‑I values, and each row can play, locate or copy its file. With backups on, Undo restores a file that a delivery replaced.

The capture is a demo project with synthetic audio and fictional file names.

Preflight

Preflight runs before every export and says what the render will and will not pass through. A blocker, a setting that would make the delivered file wrong, stops the render. A second list names where the file will differ from what you hear in the session: a per-item render, for example, takes the media items directly and skips track, folder and master processing.

In development

Named queues and auditioning

These features are in the development source, not in v3.4.4, and still need manual testing in REAPER. They are for revising a set of sounds: exporting again only what changed, then listening to the result in the same session.

  • Queue saved with the project. Separated selected clips become groups, each with its own delivery name, saved into the REAPER project. A new export can include only the groups that changed, without renumbering the rest.

  • Auditioning in Media Explorer. After an export, the folder opens in REAPER’s Media Explorer with its volume and loop controls, or in the system file browser.

  • Game SFX review. An optional review reads the delivered files’ measurements and flags headroom and low-level concerns, without changing audio, failing a delivery or holding every effect to one LUFS target.
