the concept

Shadow Frames is a first-person horror game where audio is the only weapon. There are no UI markers, no health bars, no minimap. Players navigate a procedurally shifting environment using only what they can hear.

Every threat has a distinct sonic signature. Every room tells a story through its ambient sound bed. The player's survival depends entirely on listening — identifying what's nearby, gauging distance, and deciding whether to move or stay still.

I was the audio lead on an 8-person team. I designed the full audio pipeline from recording through implementation, built the core gameplay systems in Wwise and Unreal, and managed the mix across 5.1 surround.

what i built

threat detection system

Each enemy type has a layered sound profile — footsteps, breathing, ambient hum — controlled by distance-based RTPCs in Wwise. As threats approach, frequency content shifts from low rumble to mid-range detail, giving the player precise spatial information without any visual cue. I built a hysteresis state machine so audio transitions don't flicker when enemies hover at threshold distances.

environmental storytelling

Every room has a unique ambient bed built from 3-5 layered loops: mechanical hum, wind, water drip, electrical buzz, distant voices. I recorded most source material myself — metal scrapes, concrete impacts, HVAC recordings from campus buildings. The beds shift based on room state, so a room you've already cleared sounds different from one with an active threat.

adaptive music

The score is driven by a Wwise state machine with four intensity levels: explore, tension, chase, and aftermath. Transitions use musical stingers timed to bar boundaries so they never feel jarring. I composed the stems in Reaper, targeting a dark ambient palette — low drones, granular textures, sparse piano hits. The chase state layers in percussive elements that sync to the player's movement speed.

challenge #1

problem

With 120+ Wwise events firing in a dense horror environment, we regularly hit our 32-voice limit. Rooms with multiple threats and ambient layers would cause audible voice stealing — critical gameplay audio would cut out at the worst moments.

solution

I built a priority system using Wwise voice management with custom C++ hooks. Threat-related sounds always take priority over ambient. I added distance-based culling so off-screen ambient layers auto-duck when the voice budget gets tight. Environmental loops use virtual voices that resume seamlessly.

result

Zero audible voice stealing in playtests. Threat audio never drops, even in worst-case 4-enemy scenarios.

challenge #2

problem

Early playtests showed 80-120ms audio latency on threat proximity changes. Players couldn't react in time — the game felt sluggish and unfair. The delay came from Wwise RTPC smoothing combined with Blueprint tick overhead.

solution

I moved distance calculations to C++ (bypassing Blueprint tick), reduced RTPC interpolation time for critical game states, and added a fast-path for sudden proximity changes that skips smoothing entirely. For the chase state specifically, I pre-loaded all stems into memory so there's zero streaming delay on transitions.

result

Latency dropped from 80-120ms to under 50ms. Playtesters described the audio as "instant" and threat detection accuracy improved across the board.
