Local Student Builds Audio System Where Sound Is the Only Weapon

Shadow Frames project earns praise; players navigate horror game using ears alone

By Igor Szuniewicz, Audio Lead  ·  Shadow Frames Team

Kortrijk — A 21-year-old game audio student at Howest Digital Arts & Entertainment has built an audio-first horror game in which the player carries no weapons, no map, and no HUD. The only tool for survival is listening. The project, titled Shadow Frames, has been in development since September 2025 by a small team of students, with Igor Szuniewicz serving as sole audio designer and implementer.

The system, constructed in Wwise and Unreal Engine 5, drives over 120 audio events that respond dynamically to player proximity, room acoustics, and creature behavior. Szuniewicz designed a spatial audio pipeline where every sound in the environment carries gameplay information—footstep textures change with surface type, ambient drones shift with threat level, and enemies emit distinct audio signatures that the player must learn to decode.

“There are no UI markers,” Szuniewicz explained in a recent interview. “Players find anomalies by listening. If you hear a low rumble on your left, that is the creature. If you hear glass cracking under your feet, you are in the wrong corridor. Every sound is a signal.”

The technical challenge was considerable. With no visual cues to fall back on, the audio mix had to be precise enough that players could make split-second decisions based on spatial information alone. Szuniewicz implemented a hysteresis-based state machine for creature audio—preventing the jarring on-off switching that typically plagues proximity-triggered sound events—and used Wwise RTPCs to create smooth, continuous transitions between ambient states.

Memory management proved equally demanding. The team’s target platform imposed strict voice count limits: no more than 32 simultaneous voices. Szuniewicz prioritized voices using a custom system that ranks sounds by gameplay relevance, ensuring that critical audio—creature proximity cues, surface warnings, puzzle feedback—always takes precedence over atmospheric fill.

The project represents a growing trend in independent game development: games that treat audio not as accompaniment but as a core mechanic. Szuniewicz noted that the constraints forced creative solutions. “When sound is the gameplay, you cannot afford a single wasted voice or a misleading reverb tail.”

ML Classifier Achieves 92% Accuracy in 45ms

Transientica Project · Solo Developer

Kortrijk — A real-time audio classification tool built by Szuniewicz can identify transient sounds—kicks, snares, hi-hats, claps—with 92% accuracy and a processing latency of just 45 milliseconds.

The tool, called Transientica, uses a Support Vector Machine trained on spectral features extracted via FFT analysis. Szuniewicz chose SVM over neural network approaches after benchmarking showed the lighter model met accuracy targets while running comfortably within the 50ms latency budget required for real-time audio workflows.

Built in Python with a custom GUI, the system processes incoming audio, classifies the transient type, and outputs results—all within a single buffer cycle. The training dataset comprised over 3,000 labeled samples across four percussion categories.

One-Man Audio Dept. Ships 70 Wwise Events for Cozy Horror Title

Not Today, Darling! · Solo Audio Designer

Kortrijk — As the sole audio designer on Not Today, Darling!, a cozy horror game set in a haunted flower shop, Szuniewicz built and shipped a complete audio pipeline—70 Wwise events, 200+ sound assets, all within a 180MB memory budget.

The 32-voice limit forced aggressive optimization. Szuniewicz used MetaSounds in Unreal Engine 5 for procedural ambient generation, replacing what would have been dozens of static audio files with a handful of node graphs that produce infinite variation at near-zero memory cost.

AudioQ: Student Builds VST Sampler From Scratch Using JUCE

Audio Programming · Solo Project

In a feat of low-level audio programming, Szuniewicz developed a fully functional VST3/AU sampler plugin using the JUCE framework and C++. The plugin, AudioQ, features multi-sample layering, ADSR envelope shaping, and real-time filter modulation.

The project required writing a custom audio engine from scratch—no templates, no starter kits. “I wanted to understand every sample that passes through the buffer,” Szuniewicz said. The result is a lightweight instrument that loads in under 200ms in major DAWs including Ableton Live, Reaper, and Logic Pro.

8-Day Score Saves Graduation Film After Composer Drops Out

Ray Animation · Emergency Composer

When the original composer for the student animation film Ray withdrew just eight days before the deadline, Szuniewicz stepped in to write, record, and deliver the entire score. The result: a complete orchestral soundtrack synchronized to a four-minute animated short.

Working 14-hour days, he composed six distinct cues, mixing live-recorded guitar and piano with orchestral sample libraries. Sync points were hit frame-by-frame using Reaper’s tempo mapping tools. The film screened on schedule.

Creature Design Goes Binaural in Amorak VR Prototype

Amorak · Sound Designer

For the VR game prototype Amorak, Szuniewicz designed a creature audio system using binaural spatialization to place monster sounds precisely in 3D space around the player’s head. The system was built in Wwise with Unreal Engine integration.

Each creature type received a distinct sonic identity built from layered synthesis and processed field recordings. The result: players could identify creature type, distance, and direction with eyes closed—a critical design goal for a horror VR experience where looking at the monster has consequences.

Editor’s Note

On Building Tools That Fix Your Own Problems

Szuniewicz has developed two internal tools for Unreal Engine audio workflows: Wwise Unreal Fixer, which automates the resolution of common Wwise-UE integration bugs, and UE Rebuilder, a build pipeline tool that cuts iteration time. Both emerged from production frustrations. “If I spend 20 minutes debugging the same issue twice, I write a tool,” he noted. Both tools are now used by teammates on current projects.
