

DEVELOPMENT STACK
Unreal Engine
Installation
During installation, do not modify the drive or the installation path.

Apart from Core Components (required), ensure that the first three optional selections are enabled for everyone.

For developers, selecting Editor symbols for debugging is mandatory.

Since our target platform is Windows, there is no need to install additional components - Target Platforms can be left unchecked.

Verification
In certain cases, the engine may not function properly, for instance, if an internet connection is lost during a hotfix installation or if engine files become corrupted. In such situations, it is advisable to verify the integrity of the engine's content. This can be done as follows:
In the Epic Games Launcher, click on the arrow button. 
In the dropdown menu, select the Verify option.

The process may take anywhere from 5 to 15 minutes. 
Once the process is complete, verify its success by launching the engine.


Source Code
After successfully installing our chosen IDE, ensure that the settings within Unreal Engine are configured correctly.
Open the project, then navigate to Editor Preferences….

In the Source Code submenu, select the desired code editor - either Visual Studio or Rider in our case.


Creating a C++ Project
To ensure that Unreal Engine is functioning correctly, we will create a simple C++ test project following the steps below.
Launch Unreal Engine.

Click on the GAMES tab, select the Third Person template, then on the right side, switch to the C++ tab. Finally, specify a desired project name and file path. Click on Create.

Project creation in progress...

If the compilation is successful, both Unreal Engine and the default code editor will open automatically. This example demonstrates the process using Rider IDE.


The project should launch without any issues.


Our test is not yet complete. Now, we will add an empty C++ class to the project.
Click on New C++ Class….

Select the Actor class and click Next.

Leave the class name as default, then click Create Class.

The Live Coding window will automatically appear, and the class compilation will begin.

If the compilation is successful, the final message in the Live Coding window should appear in green, displaying: "Successfully linked patch."
Additionally, a pop-up notification in the bottom-left corner will confirm: "Live coding succeeded."


Double-check that the compiled class is visible in Unreal Engine.
In the bottom-left corner, click on the project name (in this case, our test project was created as MyProject).
The newly created class should be visible within the folder.

Opening a C++ Project
In some cases, we need to open an existing C++ Unreal project.
Ideally, the project should include three folders (Config, Content, Source) and a .uproject file.

The following steps will demonstrate the process of successfully generating the project.
Right-click on the .uproject file, then select Show more options.

Click on Generate Visual Studio project files.

Project file generation in progress...

In addition to the existing folders, new directories have been created.

Most importantly, a .sln file has also been generated.

Next, double-click the .uproject file. A prompt will appear - click Yes to proceed.

Unreal Engine will begin building the project.

If the build is successful, the project will open.

Plugins
At this moment, apart from the default-enabled plugins, we are not using any additional plugins.
Certain custom plugins may cause compilation errors, preventing the project from launching. These must be disabled unless they are essential for the project.
One such example is the Houdini plugin. If we encounter an error message during project creation, this plugin is likely the cause:
Expecting to find a type to be declared in a module rules named 'HoudiniEngine' in 'UE5Rules, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null'. This type must derive from the 'ModuleRules' type defined by UnrealBuildTool.
The following process demonstrates how to disable it.
Locate the HoudiniEngine.uplugin file. By default, its path is:
C:\Program Files\Epic Games\UE_5.5\Engine\Plugins\Runtime\HoudiniEngine
If we cannot find it, use the Everything search application. (We will discuss the Everything application in the Other Tools section.)

Open the file in a text editor of your choice and change the EnabledByDefault value from true to false.


Save the file and reopen the desired Unreal Engine project. The project should now open without issues.

Excluding Trees
The following process demonstrates how to exclude a Tree from the Depot. In this case, we will use the rustborn folder as an example.
Click on Edit Current Workspace….

In the Basic tab, right-click and select Exclude Tree.

The icon next to the folder has changed. Click Apply.

A pop-up window will appear. Click Update, then close the window by pressing OK.


Verify that the setting was applied successfully. In the Depot tab, click on the rustborn folder and try to download its contents by pressing the Get Latest button. The Log window should display the following message: file(s) not in client view

Submitting deleted files
During development, there may be instances where an entire folder or specific files are marked using the Mark for Add... function. Before submitting them to the Depot, certain contents might be deleted. Unfortunately, Perforce lacks the intelligence to track a file's lifecycle, meaning that even after deletion, it remains listed in the Pending tab. If we attempt to submit the entire Pending list, an error will occur, attempting to upload something that no longer exists. In such cases, the Pending list must be manually cleaned.
Within the Pending list, files are displayed in two colors: blue and white. A blue entry indicates an active, existing file.

A white entry indicates a deleted or non-existent file.

Deleted files can be removed by selecting them and using the Revert option from the right-click menu.
