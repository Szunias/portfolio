# Runtime and preview-server audit — 2026-09-08

Baseline: `b6029882b47b69ec0be88737f398b14afbdbee15`.

This patch fixes reproduced defects in the active site and local preview tool.
It preserves page content, styles, routes, media files and deployment permissions.
It does not rewrite historical applications or certify the entire repository as
vulnerability-free.

## Confirmed defects and changes

| Area | Reproduction and fix |
| --- | --- |
| Local preview file isolation | A symlink under `dist` could serve a file outside the preview root. Resolve and validate canonical paths for normal files, extensionless aliases, directories and the 404 fallback. Safe internal symlinks and byte-range playback remain supported. |
| Preview error handling | A directory named `404.html` caused a 500 instead of a normal missing-page response. Only read a regular fallback file; otherwise send a plain 404. |
| Initial music queue | The featured opener was selected while the queue cursor stayed at -1. The first Next selected the opener again. Build the queue around the initial selection, including restored shuffle and an opener outside the default filter. |
| Music dialog | Clicking the dialog's own padding was treated as clicking its backdrop. Check the click coordinates against the dialog rectangle before closing. |
| Card previews | A rejected play request from an earlier hover could cancel a newer hover on the same card. A request generation now identifies which asynchronous result still owns the preview. |
| Showreel | A queued play event could reopen a player already closed by the user. Ignore the event when the video is paused, and emit the active-state notification only once per opening. |
| Email copying | Invalid mailto encoding threw outside error handling, and an older clipboard operation could replace the newest status. Validate and decode inside the guarded operation; only the newest completion owns the status and timer. |
| Contact clock | Other pointers could move or release the active drag; losing pointer capture left the clock in its scrubbing state. Track the owning pointer, handle lost capture and accept release outside the dial when capture is unavailable. |

The symlink disclosure concerns a locally running developer preview with a link
placed inside its output directory. It is not evidence that GitHub Pages leaks
files from the developer's computer. The preview still binds to loopback and is
not intended as a production server or a sandbox for a filesystem that another
process is maliciously changing during requests.

## Regression coverage

`npm test` automatically discovers the two new test files. They add 21 cases:
14 browser-runtime cases and 7 preview-server cases. The runtime tests execute
the actual source files in isolated Node VM contexts, using deliberately small
DOM/event doubles for controlled asynchronous ordering. They are not a replacement
for a browser layout engine or real media decoding. No npm dependencies are added.

Local targeted validation included the new cases and the 12 existing browser-asset
and preview-server tests. The complete test suite, including the existing SEO
cases, and the asset-dependent site build must also pass the repository's existing
pull-request CI. Consult the PR checks for that result; a targeted local run is
not a substitute for a full checkout build.

Additional Chromium checks used real DOM fixtures at 320 px and 1440 px widths:
initial selection/Next, dialog padding/backdrop, showreel close/play ordering and
malformed email copying. Media IO was mocked. This was not a complete visual
review of all deployed pages, a Safari/iOS codec test, an archive dependency audit
or a live-host penetration test. No production deployment or merge is performed
by this patch.
