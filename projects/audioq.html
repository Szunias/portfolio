JUCE Architecture

AudioProcessorValueTreeState

Parameter management system for automation and state persistence

WHAT

APVTS manages plugin parameters, handles DAW automation, and preserves state between sessions.

HOW

Parameters defined via RangedAudioParameter with min/max/default values. Automatically exposed to host for automation.

WHY

Thread-safe parameter access, automatic state management, and zero-config DAW integration.

RESULT

All parameters automatable without additional code. Plugin state persists across sessions.

PluginProcessor.cpp — Parameter Definition

WHAT: Creates and returns plugin parameters with ranges and defaults.

HOW: Each AudioParameterFloat added to vector, converted to ParameterLayout for APVTS.

WHY: Centralized definition ensures consistency. All parameters automatically automatable. 

juce::AudioProcessorValueTreeState::ParameterLayout createParameters()
{
    std::vector<std::unique_ptr<juce::RangedAudioParameter>> params;

    params.push_back(std::make_unique<juce::AudioParameterFloat>(

        "HPF", "HPF (Hz)", 20.0f, 20000.0f, 20.0f

processBlock Implementation

Real-time audio pipeline in JUCE

WHAT

Main audio callback invoked by DAW. Processes buffers in real-time.

HOW

Fetches audio from AudioFilePlayer, applies filters, compressor, and tremolo. Reads parameters via atomic pointers.

WHY

Runs in audio thread with strict timing. APVTS provides lock-free parameter access.

RESULT

Low-latency processing with correct effect order. No dropouts during parameter changes.

PluginProcessor.cpp — Audio Processing

WHAT: Applies all effects to incoming audio buffers.

HOW: Reads APVTS parameters, fetches audio, applies DSP in sequence, then final gain.

WHY: Sequential processing ensures correct order. JUCE DSP provides SIMD optimization. 

void processBlock(juce::AudioBuffer<float>& buffer, juce::MidiBuffer& midiMessages)
{
    // Volume safety check
    if (dangerousVolumeDetected) {
        buffer.clear();
        return;
    }

    float gainValue = *apvts.getRawParameterValue("GAIN");
    float tempoValue = *apvts.getRawParameterValue("TEMPO");
    float lpfCutoff = *apvts.getRawParameterValue("LPF");
    float hpfCutoff = *apvts.getRawParameterValue("HPF");

    double ratio = (double)tempoValue / 120.0;
    audioFilePlayer.setResamplingRatio(ratio);

    juce::AudioSourceChannelInfo info(buffer);
    audioFilePlayer.getNextAudioBlock(info);

    lpf.setCutoffFrequency(lpfCutoff);
    hpf.setCutoffFrequency(hpfCutoff);

    juce::dsp::AudioBlock<float> dspBlock(buffer);
    juce::dsp::ProcessContextReplacing<float> ctx(dspBlock);
    lpf.process(ctx);
    hpf.process(ctx);
    compressor.process(ctx);

    // Custom tremolo and final gain applied here...

    buffer.applyGain(gainValue);
}

Tremolo Effect Implementation

Per-sample LFO for amplitude modulation

WHAT

Amplitude modulation via low-frequency oscillator. Creates rhythmic pulsing effect.

HOW

Sine wave LFO calculated per sample. Each sample multiplied by LFO value based on depth parameter.

WHY

Manual implementation provides full control. Per-sample processing ensures smooth modulation.

RESULT

Smooth tremolo with precise rate/depth control. No aliasing or stepping artifacts.

PluginProcessor.cpp — Tremolo Implementation

WHAT: Custom tremolo using sine wave LFO for amplitude modulation.

HOW: Phase increment calculated per sample. Sine wave applied to all channels.

WHY: Per-sample processing ensures smoothness. Manual implementation allows precise behavior control. 

if (tremoloOn && tremDepth > 0.0f)
{
    int numSamples = buffer.getNumSamples();
    int numChannels = buffer.getNumChannels();

    float phaseInc = (float)(2.0 * juce::MathConstants<double>::pi * tremRate / currentSR);

    for (int sample = 0; sample < numSamples; ++sample)
    {
        float lfoVal = 0.5f + 0.5f * std::sin(tremoloPhase);
        float amplitude = (1.0f - tremDepth) + (tremDepth * lfoVal);

        for (int ch = 0; ch < numChannels; ++ch)
        {
            float* writePtr = buffer.getWritePointer(ch);
            writePtr[sample] *= amplitude;
        }

        tremoloPhase += phaseInc;
        if (tremoloPhase > juce::MathConstants<float>::twoPi)
            tremoloPhase -= juce::MathConstants<float>::twoPi;
    }
}
JUCE DSP

Filters & Compressor

DSP modules from JUCE library

WHAT

JUCE provides StateVariableTPTFilter and Compressor. SIMD-optimized for performance.

HOW

TPT filters use Topology-Preserving Transform for zero-delay. Compressor uses look-ahead and smooth envelopes.

WHY

JUCE DSP modules are optimized and tested. Saves development time, ensures quality.

RESULT

High-quality filtering and compression with low CPU. Parameters respond smoothly to changes.

PluginProcessor.cpp — DSP Setup

WHAT: Initialization in prepareToPlay, called before audio starts.

HOW: ProcessSpec defines sample rate, block size, channels. All modules prepared with same spec.

WHY: prepareToPlay called before processing. DSP modules need correct sample rate and buffer sizes. 

void prepareToPlay(double sampleRate, int samplesPerBlock)
{
    juce::dsp::ProcessSpec spec;
    spec.sampleRate = sampleRate;
    spec.maximumBlockSize = (juce::uint32)samplesPerBlock;
    spec.numChannels = 2;

    lpf.setType(juce::dsp::StateVariableTPTFilterType::lowpass);
    hpf.setType(juce::dsp::StateVariableTPTFilterType::highpass);
    lpf.prepare(spec);
    hpf.prepare(spec);
    lpf.reset();
    hpf.reset();

    compressor.prepare(spec);
    compressor.reset();
}
Audio Playback

AudioFilePlayer System

File loading, playback, and tempo manipulation

WHAT

Manages file loading, playback, looping, and tempo. Uses AudioTransportSource and ResamplingAudioSource.

HOW

Files loaded into AudioFormatReaderSource, wrapped in ResamplingAudioSource, connected to AudioTransportSource.

WHY

JUCE AudioSource architecture provides clean separation. Each source handles one responsibility.

RESULT

Smooth playback with 20-300 BPM tempo control, seamless looping, granular mode support.

AudioFilePlayer.cpp — Playback System

WHAT: AudioSource chain for playback with tempo control.

HOW: Reader wrapped in ResamplingAudioSource, connected to AudioTransportSource.

WHY: ResamplingAudioSource changes speed maintaining quality. AudioTransportSource provides play/stop/loop. 

void loadFile(juce::File file)
{
    juce::AudioFormatReader* reader = formatManager.createReaderFor(file);
    if (reader != nullptr) {
        juce::AudioFormatReaderSource* source = new juce::AudioFormatReaderSource(reader, true);

        resamplingSource.setSource(source, 0, nullptr, reader->sampleRate);
        resamplingSource.setResamplingRatio(1.0);

        transportSource.setSource(&resamplingSource, 0, nullptr, reader->sampleRate);
        transportSource.setLooping(true);
        transportSource.prepareToPlay(samplesPerBlock, sampleRate);
    }
}

    void setResamplingRatio(double ratio) {
        resamplingSource.setResamplingRatio(ratio);
    }
}
