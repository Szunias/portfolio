Technical Terms Explained

Random Container

A Wwise structure that randomly selects one sound from a pool each time it's triggered. Example: When a gun fires, it picks 1 of 6 different shot sounds. This prevents repetitive audio fatigue in games where actions happen frequently (shooting 100+ times per session). Without this, players would hear the exact same gunshot every single time, breaking immersion.

RTPC (Real-Time Parameter Control)

A system that adjusts audio based on game variables in real-time. Example: A waterfall sound gets louder as you approach it, quieter as you walk away. The game sends distance values to Wwise every frame, and Wwise smoothly adjusts volume/mixing automatically. This creates dynamic, responsive audio that reacts to player movement without manual triggers.

Auxiliary Bus (Reverb Bus)

An audio processing channel that applies environmental effects like reverb (echo). When you walk from a forest into a cave, sounds suddenly have echo - that's an auxiliary bus adding cave reverb. Multiple buses allow different spaces to sound distinct: small room reverb vs large cathedral reverb. This makes environments feel authentic and spatially believable.

State Group (Game States)

A Wwise system that changes audio based on game situations. Example: When player enters "Brain Zone", Wwise automatically loads Brain soundbank and starts Brain ambient music. When leaving, it unloads that bank and loads the next zone's audio. This enables dynamic music and ambience that responds to gameplay without manual scripting for every transition.

Soundbank

A packaged file containing audio assets and metadata. Think of it as a ZIP file of sounds that gets loaded into memory. Smart soundbank organization = better performance. Example: Loading only "Combat Sounds" bank during fights instead of loading ALL game audio at once saves 50MB+ of RAM.

Attenuation

How sound volume decreases with distance. In real life, footsteps 50 meters away are quieter than footsteps 5 meters away. Attenuation profiles control this in games: Enemy footsteps audible at 75m helps gameplay (hear threats before seeing them), while small object destruction only audible at 11m prevents audio clutter. Custom curves per sound type = better spatial awareness.

Vorbis Quality Factor (Q5, Q7, Q8)

Compression quality setting for OGG Vorbis audio codec (0 = worst quality/smallest file, 10 = best quality/largest file). Q8 for music preserves all frequencies and dynamics. Q5 for sound effects is "good enough" while saving 40% file size. Q1 for UI clicks is barely noticeable but saves 70% space. Content-aware compression = smaller builds without sacrificing important audio.

Streaming Audio

Playing audio directly from disk instead of loading it entirely into RAM. A 3-minute music track might be 25MB. Loaded in memory = 25MB RAM used. Streamed from disk = only 512KB buffer in RAM. Critical for mobile games where every MB matters. Trade-off: slight CPU cost for disk reading, but modern devices handle this easily for 1-2 music tracks.

Project 01

Boney Boogaloo

Foundation project establishing core Wwise workflows: random container architecture, voice management, and manual optimization techniques.

About This Project

Zombie shooter built with Wwise v2021.1.14 Build 8108 for Windows. First full Wwise implementation focusing on core middleware workflows: Random Container architecture for audio variation, voice management systems, and manual optimization techniques. Priority was establishing foundational workflows rather than final audio polish.

Implementation Focus

Repetitive audio in high-frequency actions (200+ gunshots per session) creates listener fatigue. Implemented Random Containers pooling 6 gunshot variations - each trigger automatically selects different audio. Combined with aggressive silence trimming and ADPCM compression to meet 50MB build constraint (achieved 35MB final footprint).

Technical Outcome

Random Containers provide middleware-level variation - single event trigger, automatic sound selection. Manual silence trimming achieved 30% file size reduction without quality degradation. ADPCM compression balanced decode efficiency with size constraints. Final build: 35MB (30% under budget).

Key Takeaway

Middleware-level variation (Random Containers) reduces code complexity compared to game-side randomization. Manual optimization workflows (trimming, compression) scale efficiently across projects. Foundational techniques established here apply to larger-scale implementations regardless of asset count.

Technical Details

Random Container Architecture

Implemented 9 Random Containers: 6 gunshot variations, 6 zombie spawns, 4 death sounds, 3 gore impacts. Each trigger automatically selects from pool without code-side randomization. Volume balancing (-2dB to -5dB) ensures consistent perceived loudness across variations.

Impact

Middleware-side solution eliminates need for game-side randomization code. Single event call in Unity, variation handled by Wwise. Reduces code complexity and iteration time - audio designer adjusts without programmer involvement.

Manual Audio Optimization

Aggressive silence trimming applied to all assets (0.19s to 1.2s per file). Gun reload: 0.495s trimmed. Announcer lines: 1.1-1.2s removed from tail. Result: 30% file size reduction (50MB → 35MB) without quality degradation.

Impact

Manual optimization saved 15MB through silence removal alone. Combined with ADPCM compression, achieved build target with 30% margin. Time-intensive for large projects but practical for 44-asset scope.

Simple Signal Flow

Direct signal routing: events → sounds → Master Bus → output. Zero effects chain minimizes CPU overhead. ADPCM/PCM compression (default conversion). Volume threshold at -80dB for automatic voice culling of inaudible sounds.

Impact

Zero DSP effects = minimal CPU overhead (sub-5ms on target hardware). -80dB threshold prevents voice limit saturation during dense combat scenarios (20+ enemies + gunfire + ambient). Automatic voice culling maintains 256 voice budget headroom.

Sequence Container for Announcer

Sequence Container (non-random) for round progression: linear playback (Round 1 → 2 → 3 → 4). Each announcer VO trimmed 1.1-1.2s from tail, volume adjusted -1dB for consistent output.

Custom Loop Region Ambience

Forest ambience with manual loop region (30.87s to 102.41s), 1.4s fade-in, 1.8s fade-out for seamless transition. Global instance limit of 1 prevents overlapping ambient loops. Custom loop editing eliminates audible artifacts.

Project 02

Ellen

Intermediate systems implementation: state-driven adaptive audio, RTPC reverb control, and content-aware compression strategies for optimization.

About This Project

Third-person action game built with Wwise v2021.1.14 for Windows. Three distinct zones: Jungle (outdoor), Main Chamber (large interior), Buildings (corridors). Implementation focus: State Groups for zone-based transitions, RTPC systems for distance-driven reverb, and content-aware compression differentiation across asset types.

Implementation Focus

Zone transitions require smooth crossfades between environmental layers without hard cuts. Compression optimization: uniform quality settings waste resources - music requires high fidelity, UI assets don't. Attenuation profiles: enemy footsteps audible at 75m for gameplay advantage, small destructibles limited to 11m to prevent audio clutter.

Technical Outcome

State Groups provide automatic transition handling: Unity trigger volumes set state, Wwise crossfades layers (6.5s duration). Content-aware compression achieved 40% size reduction: Music Q8 (maximum fidelity), SFX Q5 (balanced), UI Low (minimal). Custom attenuation: Grenadier footsteps 75m (tactical information), destructibles 11m (mix clarity).

Key Takeaway

State-driven systems enable automatic zone transitions without manual scripting. Content-aware compression allocates quality budget strategically - high fidelity where perceptible (music), aggressive compression where negligible (UI). Custom attenuation serves dual purpose: gameplay information (enemy positioning) and mix control (environmental clarity).

Technical Details

State-Driven Adaptive Ambience

Switch Container (SC_AMB) controlled by MusicZone state group. Unity trigger volumes detect zone entry, set state, Wwise handles layer crossfades (6.5s duration). ContinuousPlayback mode ensures smooth transitions without abrupt stops.

Impact

Zone transition (Jungle → Building): ambient layers crossfade over 6.5s without hard cuts. Jungle birds fade out simultaneously as building drone fades in. Middleware-level automation eliminates per-transition scripting requirements.

Compression Strategy Differentiation

Content-aware compression per asset type: Music (Vorbis Q8 - maximum fidelity), Ambience (Q7 - loop-safe), SFX (Q5 @ 44.1kHz - balanced), Voice (ADPCM - efficient decode), UI (Low - minimal footprint). Strategy achieved 40% build size reduction versus uniform compression.

Impact

Uniform Q8: excessive build size, wasted on UI assets. Uniform Q5: compressed music artifacts. Differentiated approach: optimized build size while maintaining music quality. Allocates quality budget strategically.

Dynamic Reverb System

Four auxiliary buses with Wwise RoomVerb: Cave (Hall_Medium_Dark), StoreRoom (Room_Medium), StoneBig (outdoor), StoneSmall (corridors). Unity scripts drive RTPC values (0.0-1.0) for position-based reverb crossfading.

Impact

Environmental acoustics match spatial context: cave footsteps exhibit long dark reverb tail, corridor footsteps produce short tight reflections. RTPC control enables smooth reverb transitions during zone traversal.

3D Footstep System with Surface Detection

Switch Container (SWC_Footsteps) with dual switch axes: Material (Grass/Earth/Puddle/Stone) and Locomotion (Walking/Running). Unity raycasts every 2 units of movement, SurfaceIdentifier component provides material data, switch set before event post. 3D positioning with distance-based attenuation.

Impact

Automatic surface-appropriate footstep selection (grass vs stone, walking vs running). Enemy Grenadier footsteps audible at 75m with directional positioning provides tactical threat awareness. Raycast-based detection system scales to arbitrary surface types.

Blend Containers for Layered Audio

Blend Container (BL_Teleporter_Ambient_Loop) composites two layers: AMB_Drone_Rumble_01 + SFX_Magic_Teleport_Idle_Growly_01. Simultaneous playback with 3D positioning and 65m attenuation. Single event trigger, real-time mixing in Wwise. Applied to environmental objects (teleporters, interactive elements).

Impact

Single event triggers composite audio (low rumble + magical growl). Layer balance adjustable in Wwise without code modification. Middleware-side layering provides faster iteration than pre-mixed audio files.

Project 03

Stomach Aches

Advanced optimization project: zone-based soundbank loading, RTPC-driven dynamic mixing, multi-platform builds, and mobile memory constraints.

About This Project

FPS platformer built with Wwise v2022.1.11 Build 8346 for four platforms: Windows, Mac, Android, and Android_Low (budget devices). Three body zones: Brain, Stomach, Heart. Implementation focus: zone-based soundbank loading for memory optimization, RTPC-driven distance mixing, and multi-platform builds with platform-specific compression.

Implementation Focus

Mobile RAM constraints: Android budget devices (2-3GB total system RAM) cannot support 50MB+ audio footprints. Requires zone-specific loading - load Brain audio only when in Brain zone. Stomach waterfall requires distance-based layer mixing: close proximity = splashing detail, far distance = rumble, smooth crossfades between. Memory optimization: Wwise Silence plugin versus silent WAV files.

Technical Outcome

Zone-based soundbanks: Brain (670KB) loads on demand, saves 3.8MB versus full loading. RTPC waterfall: 3 layers (Close 130KB, Mid 6.3MB, Far 3.6MB) crossfade via distance. Per-frame script updates, Wwise handles mixing. Silence plugin: 0 bytes versus 132KB WAV (80% reduction). Music streaming: 512KB buffer versus 25MB full load. Runtime footprint: 13-18MB total, Android_Low compatible.

Key Takeaway

Zone-based loading enables scalable memory management - load only active zone assets. RTPC distance mixing provides smooth audio transitions without discrete switching. Silence plugin: advanced Wwise optimization using procedural generation to eliminate file storage. Multi-platform workflow: single project generates platform-specific builds with appropriate compression (Android_Low: aggressive, Windows/Mac: full fidelity).

Technical Details

Zone-Based Soundbank Loading

Six soundbanks with dynamic loading: Init (persistent), General (persistent), BrainZone (670KB), MouthZone (384KB), StomachZone (2.8MB), Music (streaming). Unity WwiseStateBridge detects zone entry, loads corresponding bank, unloads previous. Only active zone + General loaded at runtime.

Impact

Prevents simultaneous loading of all zones (saves 3.8MB). Runtime memory: 10-15MB (General + active zone) versus 18MB+ (all zones). Critical for Android_Low devices with limited RAM. Automatic bank management via state system eliminates manual load/unload scripting.

RTPC-Driven Waterfall System

Stomach zone waterfall: 3-layer Blend Container with distance-based crossfading. Splashes_Close (130KB, 0-10m) provides high-frequency detail, Main_Mid (6.3MB, 10-50m) full-spectrum flow, Rumbling_Far (3.6MB, 50+m) low-frequency rumble. WaterfallDistanceRTPC.cs calculates player-to-waterfall distance per frame, sends RTPC value to Wwise. Total asset size: 10MB.

Impact

Distance-based layer selection: 5m = crisp splashes, 30m = full waterfall roar, 60m = deep rumble. Smooth RTPC crossfades eliminate discrete switching artifacts. 10MB footprint justified as primary environmental feature of largest zone. Spatial audio implementation without hard-coded distance triggers.

Multi-Platform Optimization

Unified soundbank structure across four platforms: Windows/Mac (full quality), Android (standard mobile), Android_Low (aggressive compression Q3 vs Q5). Platform-specific compression configured in Wwise platform settings. Single project generates all builds.

Impact

Single project maintenance for four platform builds. Android_Low receives higher compression ratios for reduced storage footprint on budget devices. Windows/Mac maintain full quality for capable hardware. Identical event structure across platforms - only compression differs. Scalable workflow for multi-platform shipping.

Streaming Audio Implementation

Brain_Song_Track streams from disk versus RAM loading. VO thoughts (220KB) remain in-memory for instant triggering. Music continuous playback, VO random triggers. Streaming: 512KB buffer versus 25MB full load per 3-minute track (98% memory reduction).

Impact

Three music tracks: 75MB RAM (full load) versus 1.5MB (streaming). Critical for mobile platforms with 2GB total RAM. Trade-off: 2-3% CPU for disk I/O, acceptable on modern devices. Enables music libraries without RAM saturation. Essential technique for mobile-constrained environments.

Wwise Silence Plugin

Procedural silence generation via Wwise Silence plugin replaces WAV files in random containers. Brain ambient: 1.5s/2s silence variations. Mouth ambient: 1.5s/2s/3s variations. Applied to all zone ambient containers requiring gap timing. Saves approximately 80% memory per silence instance.

Impact

2-second silent WAV: 352KB (44.1kHz stereo 16-bit). 2-second procedural silence: 0 bytes. Across 20 silence variations: ~7MB saved. Non-obvious optimization requiring advanced Wwise knowledge. Efficient use of middleware features for memory-constrained platforms.

Explicit Voice Management

SneezeProjectile caches playback ID on loop start, explicitly calls StopPlayingID() on destroy. Prevents orphaned audio voices. Death sounds use temporary GameObjects for spatial positioning after source destruction. Manual voice lifecycle management prevents resource leaks.

Impact

Projectile destruction without explicit stop: loop continues indefinitely at destruction position, consuming 1 voice permanently. 50 projectiles = 50 orphaned voices = voice limit saturation. StopPlayingID() prevents resource leak. Critical pattern for spawned/destroyed objects with looping audio. Maintains voice budget health.

Footstep System with Body Zone Surfaces

Material switch system adapted for body zone surfaces: Gut (soft organic), Thongue (wet surface), Skull (hard bone). Controller.cs raycasts every 2 units of movement, SurfaceIdentifier component provides material data, Material switch set before footstep event post. Architectural pattern reused from Ellen project.

Impact

Automatic surface-appropriate footstep selection: stomach = organic wet sounds, skull = hard echoing sounds. Workflow scalability: same architecture applies across projects without system redesign. Raycast-based detection extensible to arbitrary surface types.

// WaterfallDistanceRTPC.cs - Real-time distance calculation
void Update()
{
    float distance = Vector3.Distance(
        playerListener.position,
        transform.position
    );
    AkSoundEngine.SetRTPCValue(
        "DistanceToWaterfall",
        distance,
        gameObject
    );
}
