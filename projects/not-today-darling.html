Project Overview

I was the solo audio designer on a 6-person student team. Over 320 audio events, entirely built with MetaSounds.

ROLE

As the only audio person, I handled everything: sound design, implementation, and mixing. Two programmers, three artists, and 12 weeks to ship.

TECH

Built entirely on MetaSounds for procedural audio. Parameters drive real-time modulation, and priority-based mixing keeps the chaos under control.

SCOPE

Over 320 events packed into 180MB. The engine handles up to 32 concurrent voices with sub-45ms latency.

RESULT

Released on itch.io in May 2025. Windows and Linux builds support 1-4 players locally.

MetaSounds Implementation

Node-based procedural audio engine driving all gameplay sounds.

WHAT

MetaSounds generates audio procedurally using node graphs. Speed modulates pitch, surface type controls sample selection, player count scales mix complexity.

HOW

Each MetaSound asset contains parameter inputs connected to gameplay variables. Speed maps to pitch multiplier (0.8x-1.3x), surface enum selects crossfaded samples, collision force drives impact volume.

WHY

Procedural generation keeps memory footprint low while maintaining variety. One MetaSound asset replaces dozens of static audio files. Parameters respond frame-perfect to gameplay state.

RESULT

Sub-2MB per MetaSound instance. Real-time parameter response with zero latency. Infinite variation from finite assets.

Audio Architecture

Centralized systems for UI, items, and engine audio. Direct calls, no delegates.

WHAT

UAudioManager (GameInstanceSubsystem) handles global UI clicks. ItemHolderComponent centralizes pickup/use SFX per item type. GrandmaCharacter manages engine audio with EngineSpeed parameter.

HOW

UAudioManager exposes PlayUISelect() and PlayUIHover() project-wide. ItemHolderComponent uses switch statements to fire sounds based on EItemType enum. Engine audio uses UAudioComponent with SetFloatParameter for real-time speed response.

WHY

Centralized systems prevent sound duplication across Blueprints. GameInstanceSubsystem makes UI audio globally accessible. Switch statements keep item logic in one place. AudioComponent parameters enable smooth engine pitch modulation.

RESULT

Clean architecture. Zero duplication. Easy debugging. Single source of truth for each audio system.

ItemHolderComponent.cpp — Item Sounds 

// Centralized pickup sounds per item type

void UItemHolderComponent::PlayMetasound(EItemType ItemType) const
{
    switch (ItemType)
    {
    case EItemType::CreamPie:
        if (PickupSound_CreamPie)
            UGameplayStatics::PlaySound2D(this, PickupSound_CreamPie);
        break;
    case EItemType::Handpin:
        if (PickupSound_HandPin)
            UGameplayStatics::PlaySound2D(this, PickupSound_HandPin);
        break;
    }
}

Surface Transitions

Smooth crossfades between materials.

PROBLEM

Instant surface switches caused nasty pops. Rapid transitions created audio spam that buried everything else.

SOLUTION

I implemented a 150ms crossfade with a 0.2-second cooldown and an equal-power curve. Material changes sound natural now.

4-Player Mix

Priority-based. Prevents masking.

PROBLEM

With four players racing, sounds stacked on top of each other until UI feedback became completely inaudible.

SOLUTION

I capped collisions at four simultaneous events, applied dedicated EQ to each slot, and added sidechain ducking (-6dB with 50ms attack and 200ms release).
